# 가상 독서 목록 앱: 책 조회·수정 기능의 범위와 진행 방향

이번 초안은 책 추가·제목 검색·읽기 상태 변경·짧은 메모 수정의 범위를 묻습니다.
화면 시안과 편집 범위, 보관·동기화·예시 데이터·결과 공유·키보드 조작을 결정합니다.
저장할 값과 저장 실패 때의 계약은 다음 설계 단계에서 따로 확인받습니다.

가상 초안 · 답변 대기 · 2030-01-01 기준

## 결정할 것

### 1. 화면 시안을 따로 만들까요?
- 권장: 책 목록과 편집 창을 한 화면에 담은 시안을 먼저 만듭니다. 책을 고른 뒤 메모를 바꾸는 흐름을 구현 전에 확인할 수 있습니다.
- 대안: 시안 없이 목록부터 구현합니다. 화면 구성이 맞지 않으면 구현한 뒤 배치를 다시 고쳐야 합니다.

### 2. 어떤 값까지 고칠 수 있게 할까요?
- 권장: 제목·저자·읽기 상태·메모를 수정할 수 있게 합니다. 표지 이미지와 별점은 다음 버전으로 미룹니다.
- 알아 둘 점: 저장을 누르기 전에는 파일을 바꾸지 않습니다. 저장에 실패하면 입력한 내용을 화면에 남기고 다시 시도할 수 있게 합니다. 여러 창에서 같은 파일을 수정하는 경우는 이번 범위에 넣지 않습니다.
- 대안: 표지 이미지와 별점도 함께 편집합니다. 이미지 저장 위치와 파일이 없을 때의 표시를 추가로 정해야 합니다.

### 3. 책을 지우는 기능도 넣을까요?
- 권장: 첫 버전에서는 보관 상태로 숨기고, 완전히 지우는 기능은 뺍니다. 잘못 누르더라도 목록에서 다시 꺼낼 수 있습니다.
- 대안: 삭제 기능을 넣습니다. 복구 가능한 기간과 백업 방식은 저장 설계에서 별도로 정해야 합니다.

### 4. 다른 기기에서도 같은 목록을 볼 수 있게 할까요?
- 권장: 첫 버전은 이 PC의 파일 하나에 저장합니다. 로그인 없이 사용할 수 있지만 다른 기기와 자동으로 맞춰지지는 않습니다.
- 대안: 기기 간 동기화를 넣습니다. 계정과 저장 서비스가 필요하므로 비용·보관할 개인정보·연결 실패 때의 동작을 별도로 확인받아야 합니다.

### 5. 처음 켤 때 예시 책을 넣어 둘까요?
- 권장: 사용자가 원할 때만 가상의 예시 책을 불러옵니다. 빈 목록으로 시작할 수 있고 개인 독서 기록과 예시를 구분하기도 쉽습니다.
- 대안: 처음 실행하면 예시 책을 바로 넣습니다. 지우지 않으면 실제 목록과 섞이므로 예시 표시가 필요합니다.

### 6. 결과는 어떤 형태로 공유할까요?
- 권장: 가상의 책만 넣은 화면 캡처와 실행 방법을 공유합니다. 개인 독서 기록은 포함하지 않습니다.
- 대안: 누구나 눌러 볼 수 있는 데모를 공개합니다. 공개할 주소와 데이터, 배포 여부는 구현 결과를 본 뒤 따로 결정합니다. 이번 범위 승인만으로 배포하지 않습니다.

### 7. 키보드만으로도 편집할 수 있게 할까요?
- 권장: 검색에서 목록을 거쳐 편집 창까지 이동하고 저장할 수 있게 합니다. 시안에서 이동 순서를 정하고 구현 뒤 실제 키보드 조작으로 확인합니다.
- 대안: 첫 버전은 마우스 조작만 지원합니다. 키보드 이동을 나중에 넣으면 화면의 이동 순서를 다시 손볼 수 있습니다.

## 나중으로 미루는 것과 아예 빼는 것
- 나중으로 미룸: 파일 가져오기·내보내기, 독서 통계, 표지 이미지, 별점
- 아예 뺌: 책 구매·대여, 결제, 다른 사람의 독서 기록 조회

## 기술 근거가 많은 질문 한 개: 가상 개인 우편

아래 사실·이름·번호는 모두 가상의 개인 우편 사례이며 실제 프로젝트 근거가 아니다.
화면 복구 동작만 고르는 질문으로 스키마·요청·응답은 이번 승인 대상이 아니어서 표가 없다. 설계 승인 사례의 표 보존과 구분해 읽는다.

**기술적 원문**

```text
가상 결정 D1, 원문 r2: 서버는 이미 받은 우편의 재수령에 AlreadyReceived 오류와 CurrentMailState를 보냄.
공통 오류 전달은 code·message만 넘겨 현재 수령 상태가 빠짐. 우편 화면은 아직 더미 연결.
r2에는 forwardRawError 설정만 켜면 화면이 자동 갱신된다는 주장이 있으나, 현재 설정값과 실제 서버 연결 동작은 미확인.
권장: 이미 받은 우편 오류 때 목록 재조회. 우편 서버 동작 유지. 조회 실패 시 화면 갱신 안 됨.
대안: 공통 오류 전달에서 상태를 보존하고 우편 화면에 연결. 우편 서버의 오류 계약은 유지하나 공통 전달 변경은 전체 라우트에 영향.
대안: 이미 받은 우편도 성공 응답으로 변경. 우편 서버의 기존 오류 계약과 컨트롤러 동작 수정 필요.
```

**사람용 완성본**

### 1. 이미 받은 우편을 다시 누르면 화면을 어떻게 맞출까요?

서버는 이미 받은 우편에 오류로 답하고, 현재 수령 상태는 화면까지 전달되지 않습니다.
우편 화면은 아직 더미 연결이어서 실제 서버에서 갱신되는지는 확인하지 못했습니다.

- 권장: 우편 서버 동작을 유지하고 목록을 다시 조회합니다. 조회가 실패하면 화면은 갱신되지 않습니다.
- 대안: 공통 오류 전달과 우편 화면을 고쳐 서버가 보낸 상태를 반영합니다. 우편 서버의 오류 계약은 유지하지만 공통 전달 변경은 전체 라우트에 영향을 줍니다.
- 대안: 이미 받은 우편도 성공으로 답하게 바꿉니다. 우편 서버의 기존 오류 계약과 컨트롤러 동작을 수정해야 합니다.

AI 상세에는 전달 필드·D1·r2, 설정만으로 해결된다는 원문의 주장과 현재 미확인인 근거를 보존했다.
사람용에는 각 선택에서 서버를 고치는지, 실패하면 화면이 어떻게 되는지, 다른 라우트에 영향을 주는지를 남겼다.
