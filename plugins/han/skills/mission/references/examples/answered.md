# 답변 완료 기록 예시

개인 독서 목록 앱을 가정해 처음부터 만든 예시다. 설계·질문·답·날짜는 모두 가상이며 실제 사용자의 승인이나 현재 작업 상태를 나타내지 않는다.
설계 승인 예시의 r3에 답한 뒤 `--editorial`로 문구를 정리한 r4의 현재 문서다. 문항 id·답·상태·승인 범위는 유지하고 실제 현재 선택·유효 조건만 문서 `body`에 쓴다. 충돌 처리·적용 범위는 명세와 승인 범위 절에서 이미 명확해 현재 결과에 반복하지 않는다.
질문 정의·선택지·답 원문·날짜·대상 개정·승인 범위는 JSON 정본과 별도 생성 이력에 온전히 남는다. 상태 머리글·미답 문항·전체 이력 링크는 CLI 생성 영역이고, 현재 결과는 작성자가 문서 `body`에 쓴 산문이다.

# 독서 상태 저장·변경 설계 기록

<!-- doc-id=confirm-A1 revision=4 -->

독서 상태와 수정 번호를 함께 저장합니다. 사용자가 본 수정 번호를 대조해 여러 창의 편집 충돌을 처리합니다.

처리됨

## 현재 명세

### BookEntry

| 컬럼 | 타입 | 키 | 제약 | 설명 |
| --- | --- | --- | --- | --- |
| Id | int64 | PK | 0보다 큼 | 책 항목 번호 |
| Title | string | 없음 | 1~200자 | 책 제목 |
| ReadingState | enum | 없음 | Planned, Reading, Finished | 독서 상태 |
| Revision | int32 | 없음 | 1 이상, 수정마다 1 증가 | 수정 번호 |

### ChangeReadingState

수정 번호 비교와 독서 상태 저장은 함께 처리합니다. 수정 번호가 다르면 저장하지 않고 사용자가 고른 상태를 화면에 남깁니다.

| 요청 필드 | 타입 | 제약·설명 |
| --- | --- | --- |
| EntryId | int64 | 존재하는 책 항목 번호 |
| ExpectedRevision | int32 | 사용자가 본 수정 번호 |
| ReadingState | enum | Planned, Reading, Finished |

| 응답 필드 | 타입 | 제약·설명 |
| --- | --- | --- |
| Result | enum | Success, EntryNotFound, RevisionConflict |
| ReadingState | enum | 현재 저장된 독서 상태 |
| Revision | int32 | 현재 저장된 수정 번호 |

## 승인 범위와 제외 조건

개인 독서 목록의 저장 구조·상태 변경과 화면 처리에 적용합니다.
기기 동기화·파일 가져오기·배포는 제외합니다. 동시 요청 결과는 구현 뒤 검증해야 합니다.

[현재 명세와 승인 근거](details/confirm-A1.md)

## 현재 결과

빈 목록으로 시작합니다. 사용자가 직접 추가하는 책에만 적용합니다.
