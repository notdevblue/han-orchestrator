# 사람에게 공유할 문서

원문과 아래의 해당 양식·완성 예시로 쓴다. 핵심만 짧고 간결하게 요약하고, 예시는 문체와 순서만 참고한다. 예시의 사실이나 선택지는 가져오지 않는다.
모든 케이스를 읽거나 양식의 빈 절을 전부 채울 필요는 없다.

## 이번 문서에 맞는 자료

| 문서 | 양식 | 완성 예시 |
| --- | --- | --- |
| 범위·방향을 묻는 질문, 확인 B·C, 멈춤 질문 | [질문](confirm-template.md) | [독서 목록 범위 질문](examples/question.md) |
| 스키마·통신 구조를 승인받는 확인 A | [설계 승인](templates/design-confirm.md) | [독서 상태 저장·변경 설계](examples/design-confirm.md) |
| 결과와 다음 일을 알리는 보고 | [보고](templates/report.md) | [우편 구현 보고](examples/report.md) |
| 답이 끝난 확인·질문을 정리하는 기록 | [답변 완료 기록](templates/answered.md) | [독서 상태 설계의 현재 결과](examples/answered.md) |

설계 승인에 대한 질문이면 설계 승인 자료를 고른다. 보고서에서 이미 다른 확인 문서가 묻는 선택은 결과와 영향을 짧게 알리고
그 문서로 연결한다. 확인 C의 피드백 반영 후보는 distill 결과가 있을 때만 질문으로 붙인다.

## 보존할 것

- 질문 id·번호·선택지의 의미·사용자 답·상태와 승인 범위를 바꾸지 않는다. 담당자·선행 조건·확인 시점·실패 결과도 판단의 일부다. 끝난 답은 다시 묻지 않는다.
- 서두에는 현재 목적·결정할 것 또는 결과만 쓴다. 과거 상태·철회·정정·수정 이유·문서를 어떻게 정리했는지는 공유 본문과 현재 상세에 쓰지 않는다. 유효하지 않은 설계는 현재 승인 대상으로 남기지 않는다.
- 질문에는 선택·이유·판단에 필요한 영향을, 설계 절에는 정확한 계약을, 범위 절에는 적용 대상·제외 조건을 둔다. 같은 동작·수치·제약·위험·승인 경계를 여러 절에서 다시 풀어 쓰지 않는다. 짧은 요약은 허용하되 전체 설명을 복제하지 않는다.
- 끝난 문항은 작성자가 문서 `body`에 실제 현재 선택·유효 조건을 쓴다. 다른 절에서 명확하면 별도 결과 요약은 만들지 않는다. 답 기록 뒤 서두·명세·관련 질문의 대기 안내도 최신 답과 대조해 고친다. 상태 머리글만 맞아도 본문이 맞는 것은 아니다.
- 이번에 승인할 테이블의 컬럼·타입·키·제약과 요청·응답 구조는 최신 한 벌을 본문에 직접 싣는다. 변경점만 보고 승인하게 만들지 않는다.
- 본문에 없는 기술 세부·확인 근거는 `details/<id>.md`에 둔다. 본문의 승인 표·계약을 상세에 다시 복제하지 않는다. 질문 정의·답 원문·날짜·대상 개정·승인 범위는 JSON 정본·`details/history/<id>.md`·기존 개정 보관에 온전히 남긴다.
- `sfid`·`remote-config`처럼 익숙한 용어는 유지한다.
- 확인·추론·미확인을 구분하고, 조건에 따라 달라지는 결과는 조건과 함께 쓴다. 대상은 실제 이름으로 부른다.
- 각 문서는 해당 판단에 필요한 사실을 갖춘다. 다른 문서의 전체 설명은 복제하지 않고 필요한 영향과 정본 링크만 둔다. 이 일을 맡은 사람이면 이미 아는 내용은 쓰지 않는다.

작성자는 현재 상태만 있는지, 같은 사실이 반복되지 않는지, 고른 예시와 문체·순서가 맞는지, 원문·현재 답과 의미·판단 조건이 같은지 대조한다. 보고는 결과·남은 작업을, 확인 문서는 결정·승인 조건을 중심으로 쓴다. 빈 절과 미작성 양식은 공유하지 않는다. 상태 머리글과 이력 링크는 CLI에 맡긴다.
별도 검토자에게는 먼저 완성 본문·공통 규칙·고른 양식·예시만 전달해 간결성과 문체·순서를 대조받는다. 그 뒤 같은 검토자에게 원문·최신 답을 전달해 의미와 판단 조건을 확인받는다.
작성자는 검토 의견도 원문·현재 답에 대조해 고친 뒤 반환한다. 코디네이터가 나중에 문장을 고치는 방식으로 통과시키지 않는다. 자동 검사는 이 대조를 대신하지 않는다.

## 새 작성자에게 넘길 자료

재작성은 변환 전 원문 보관본(선택지·설계), JSON 정본·생성 이력과 현재 문서·관련 질문에서 이미 받은 최신 답(정정·상태)을 함께 전달한다. 새 문서는 원문 보관본이 없음을 명시한다.
공통 규칙·이 파일·고른 양식·예시의 실제 경로와 문서 id·개정·출력·상세·이력 위치를 지정한다. 공통 규칙은 주입된 `사람용 문서 자료` 경로를 쓴다.

## 기존 문서를 함께 정리할 때

먼저 파일의 역할·원문 해시·답·승인 상태를 기록한다. 완료·중단 미션도 요청 범위에 포함되면 현재 유효한 결정과 적용 범위만 공유한다.
기존 질문 정의·답 원문·날짜·대상 개정·승인 범위는 정본과 이력에 그대로 보존하고, 현재 본문·상세는 현재 상태로 고쳐 쓴다.
이력으로 옮길 내용은 발행 전에 보관 위치와 누락 여부를 검토한다. `mission.md`·상태 TSV, 실행 로그·스크린샷·TSV·원문 보존본은 문체를 바꾸는 대상이 아니다.
동시에 바뀐 원문은 다시 읽어 반영한다. 확인하지 않은 과거 상태를 오늘 확인한 사실로 쓰지 않는다.
