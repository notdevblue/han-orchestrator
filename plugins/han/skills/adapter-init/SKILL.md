# 미션 어댑터 만들기

어댑터는 `/han:mission`이 프로젝트마다 다른 값을 읽는 유일한 곳이다. 계약은
`../mission/references/adapter-schema.md`. 값은 추측하지 않고 프로젝트 문서·도구 `--help`·설정
파일에서 확인한 것만 쓴다. 문서와 코드가 어긋나면 코드를 따른다.

## 1. 위치와 범위 묻기

먼저 사용자에게 묻는다.

- **어디에 둘지** — 개인 레지스트리(기본, VCS에 안 올라감: 환경변수 `HAN_ADAPTERS_DIR`이 가리키는 폴더의
  `<이름>/` + `projects.json`의 `roots`, 변수는 SessionStart 훅이 플러그인 설정 `adapters_dir`에서 넣음)
  또는 저장소 안(`<프로젝트>/.claude/orchestrator/`, 팀과 공유). 개인이면 레지스트리 `roots`에 이 프로젝트 폴더를 넣는다.
  변수가 비어 있으면 `adapters_dir`이 설정 안 된 것이니 먼저 사용자에게 알리고 README 설치 단계로 안내한다.
- **슬롯을 쓸지** — 쓰면 슬롯을 둘 상위 폴더(`slots.root`)와 슬롯 개수(기본 권장 2~3개. 더 필요하면 나중에 `slots.names`에 이름을 더하고 그때 `create <이름>`). 슬롯 하나가 워크스페이스 하나만큼
  디스크를 쓰므로 그 드라이브의 여유 공간을 같이 보여 준다. 슬롯 폴더 glob(`<root>/*`)도 레지스트리 `roots`에 넣는다.
  슬롯 설정은 PC마다 달라서 개인 레지스트리 어댑터에만 두고, 사람마다 다른 `slots.root`·`slots.client`·`slots.mainClient`는
  `local.json`에 쓴다(예시는 `local.example.json`).

이미 어댑터가 있으면 갱신 모드다. 새로 쓰지 않고, 확인한 값과 다른 칸만 골라 제안한다.

## 2. 조사

`researcher`(없으면 읽기 전용 에이전트)를 주제별로 병렬로 띄운다. 쓰기 명령은 금지시킨다.

| 주제 | 알아낼 것 |
| --- | --- |
| VCS | 종류, 작업 폴더 대비 루트 상대 경로, 작업 단위(CL·브랜치) 만들기, 파일 열기·추가, 체크포인트(shelve·커밋), 설명 인코딩 함정, 기본 작업 단위 금지류 규칙. VCS 래퍼 도구가 있으면 `--help` 전체 명령 목록에서 submit·파일 이동·워크스페이스 삭제·가져오기에 해당하는 것을 찾는다 |
| submit | 기본 정책, 게이트 명령과 사전 판별 옵션, 소요 시간, 예외(문서 CL 등) |
| 검증 | 엔진 버전과 에디터 자동화 수단(MCP 서버·도구 이름, CLI 가능 여부), 서버 빌드·테스트, 데이터 파이프라인, 문서 lint, 공유 자원 규칙 |
| 하네스 | 규칙·라우터·워크플로 문서, 에이전트 이름, 리뷰·리뷰 루프·PoC 스킬 이름 |
| 사람 확인 | 기계로 판정 못 하는 변경 종류, 독점 락 파일(Perforce typemap `+l`, git `lockable`) |
| 상태 폴더 | VCS에 올라가지 않는 로컬 폴더 후보와 그 근거(ignore 규칙) |
| 슬롯 준비 | 슬롯을 쓰면: 새 워크스페이스가 빌드 가능해지기까지 필요한 것(링크·생성물·엔진 캐시·IDE 프로젝트 파일), 신규 팀원 온보딩 문서 |

## 3. 초안

- `adapter.json`: 계약의 모든 키를 채운다. `stages`는 프로젝트의 실제 작업 순서로, PoC 스킬이 없으면
  `design` 단계를 뺀다. `verify.backend`는 엔진 자동화 수단에 맞춘다(Unity 6 미만이면 `cli` 불가).
  `roles.verify`는 `han:verifier`로 두고 검증·Unity Play 실행은 Haiku 5.5 / medium 하나에 맡긴다.
- `guard.deny`: 미션 중 막을 명령. submit·머지·푸시, 이력 삭제, 남의 작업 단위를 건드리는 명령,
  공유 작업 공간 동기화, 기본 작업 단위로 여는 명령. 실행 파일 이름 변형(`.exe`, `.bat`, 래퍼 도구)과 동사 별칭까지.
  가드는 명령을 조각으로 나눠 검사하므로(계약의 "가드") 규칙은 `^`로 조각 첫머리에 고정하고
  실행 파일 바로 뒤 동사를 보게 쓴다. 파일 경로 속 단어(`Foo.Sync.cs`, `packages-lock.json`)가 걸리지 않게 한다.
  변수로 감춘 실행 파일까지 잡으려면 동사 단독 걸림줄(예: `(?:^|\s)submit(?:\s|$)`)을 하나 둔다.
- `adapter.md`: 계약이 말하는 절을 쓴다. 명령은 복사해 쓸 수 있는 형태로, 함정은 한 줄씩.
  공유 저장소에 둘 어댑터라면 개인 값(이름, 작업 공간 이름, 경로)을 넣지 않는다.

## 4. 점검

```
python "${CLAUDE_PLUGIN_ROOT}/skills/adapter-init/scripts/check_guard.py" --doctor
python "${CLAUDE_PLUGIN_ROOT}/skills/adapter-init/scripts/check_guard.py" <adapter.json|레지스트리 어댑터 이름> <cases.json>
```

두 번째 인자를 생략하면 어댑터 옆의 `guard-cases.json`을 쓴다. 어댑터·표본 파일을 못 읽으면 `ERROR` 한 줄과 종료 코드 3이다.

- `--doctor`: 가드 훅이 쓰는 `python`이 이 PC에서 실제로 실행되는지(스토어 스텁이 아닌지) 본다.
- 표본: 막아야 할 명령과, 미션이 실제로 써야 해서 통과해야 할 명령(상태 확인, 번호 작업 단위에 열기,
  체크포인트, 검증 명령)을 둘 다 넣는다. 다음도 꼭 넣는다.
  - 여러 줄 명령(줄 이음), 이어 붙인 명령(`a && b`, `a; b`), 파이프·블록(`| xargs …`, `ForEach-Object { … }`)
  - 실행 파일을 변수에 담아 부르는 형태(프로젝트 문서에 실린 관용구 그대로)
  - 경로에 금지 단어가 든 실제 파일(저장소에서 찾아서)
  - 작업 단위 번호를 변수로 넘기거나 붙여 쓰는 형태(`-c $CL`, `-c123`)
- 표본은 JSON `[{"expect": "deny|allow", "command": "...", "tool": "Bash|PowerShell"}]`. 어긋남이 0이어야 다음으로 간다.
  판정은 가드 훅과 같은 함수를 쓰고, 어댑터 옆 `local.json`도 훅처럼 깊게 병합해서 읽는다. 표본 파일은 어댑터 옆(개인 레지스트리) 또는 상태 폴더에 두고 VCS에 올리지 않는다.

## 5. 확인과 쓰기

- 초안 두 파일과 점검 결과, 확인 못 한 값(미확인)을 보여 주고 승인받는다.
- 상태 폴더가 VCS ignore에 들어 있는지 다시 확인한다. 아니면 쓰기 전에 사용자에게 알린다.
- 저장소 안에 두기로 했으면 프로젝트 VCS 규칙대로 번호 작업 단위에 넣고, submit은 하지 않는다.
  라우터 문서(있으면)에 미션 행을 더하자고 제안한다. 직접 고치는 건 승인받은 것만.
- 슬롯을 쓰기로 했으면 `/han:slots create`로 첫 슬롯을 만들어 `adapter.md`의 "슬롯 준비" 시간을 채운다.
